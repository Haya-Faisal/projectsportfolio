Features

Password‑Protected Landing & Envelope System

  • Shared Password Gate: Single password (Mrs.Zaheed) controls access – no per‑user accounts, ideal for small groups.
  • Three Envelope States: Last Month (read‑only archive), This Month (add answers), Next Month (suggest questions).
  • Automatic Month Rotation: On each load, the app verifies and auto‑creates Firestore documents for current + next month, guaranteeing seamless transitions.
  • Custom SVG Envelopes: Visually distinct designs for each month with badges (“Read only”, “Add answers”, “Suggest questions”).

Real‑time Q&A Subsystem

  • Firestore Live Listeners: onSnapshot queries provide instant updates when new answers or questions are posted, without page refreshes.
  • Per‑Month Subcollections: Each month document contains a questions subcollection, storing question text, suggestedBy name, answers array, and timestamps.
  • Answer & Question Submission: Atomic updates using arrayUnion for answers, and addDoc for new questions – all with optimistic UI feedback.
  • Read‑only Archives: Past months render answers in elegant card layout, preserving the group’s history.

Responsive Vintage Interface

  • Glassmorphism & Blur Effects: backdrop-filter: blur(12px) and soft gradients create a tactile “letter” aesthetic.
  • Mobile‑First Layout: Sticky top bars, safe‑area insets, and touch‑friendly buttons work flawlessly on any device.
  • Toast Notifications: Non‑intrusive feedback for every submission, error, or validation message.

Technical Stack

HTML5 CSS3 Vanilla JavaScript (ES6 Modules) Firebase Firestore (NoSQL) Firebase SDK v10.8 Google Fonts (Playfair Display / Lora) Inline SVG

Performance & Data Optimizations

  • Real‑time Listener Cleanup: Unsubscribes from Firestore when leaving the letter view to prevent memory leaks.
  • Escaped User Input: Custom escHtml() prevents XSS by escaping <, >, &, and quotes before rendering.
  • Lazy Month Creation: Month documents are only created when needed, keeping the database lean.
  • Efficient Query Ordering: Questions are ordered by createdAt (ascending) to preserve conversation flow.

Automatic Month Rotation (Ensuring Continuity)

async function ensureMonthsExist() {
  const currentKey = getMonthKey(0);
  const currentSnap = await getDoc(doc(db, 'months', currentKey));
  if (!currentSnap.exists()) {
    await setDoc(doc(db, 'months', currentKey), {
      createdAt: serverTimestamp(),
      label: getMonthLabel(0)
    });
  }
  // same for next month (offset +1)
}

Dynamic Envelope Labels

function getMonthLabel(offset = 0) {
  const d = new Date();
  const totalMonths = d.getFullYear() * 12 + d.getMonth() + offset;
  const y = Math.floor(totalMonths / 12);
  const m = totalMonths % 12;
  return `${MONTH_NAMES[m]} ${y}`;
}

Challenges & Solutions

Challenge: Real‑time updates without over‑fetching

Solution: Used Firestore onSnapshot with subcollection queries; only changed documents trigger UI re‑renders, while automatic unsubscription prevents background listeners when not needed.

Challenge: Preventing XSS from user input

Solution: Implemented escHtml() helper that escapes &, <, >, and " before rendering any user‑supplied text – securing all Q&A entries.

Challenge: Seamless month transition without manual admin

Solution: getMonthKey(offset) generates YYYY‑MM keys; on every load, the app checks and auto‑creates missing month documents, ensuring that next month’s “suggestions” folder is always ready.

Challenge: Mobile UX with sticky header & safe areas

Solution: Used position: sticky on the letter‑view top bar and env(safe-area-inset-bottom) to avoid notch/gesture overlap on modern iPhones.

Deployment Architecture

Static Hosting (Vercel / Netlify / Firebase Hosting)
        ↓
Firebase Firestore (real‑time NoSQL database)
        ↓
Client Browser (Vanilla JS + Firestore SDK)
        ↓
End‑to‑end encryption via Firebase security rules (optional)

The entire frontend is a single HTML/CSS/JS file, making it portable and easy to deploy on any static web server. Firestore handles all backend logic, authentication (password gate is client‑side; for production one would add Firebase Auth or security rules).

System Data Flow

User enters password → Landing page validates → Show envelope dashboard
        ↓
User clicks envelope (last/current/next)
        ↓
Firestore real‑time listener attached to months/{monthKey}/questions
        ↓
Render view based on month type:
  - Last: display questions + existing answers (read‑only)
  - Current: display questions + form to add an answer
  - Next: display suggested questions + form to suggest new question
        ↓
User submits answer/question → Firestore update (arrayUnion or addDoc)
        ↓
Snapshot listener fires → all connected clients see the update instantly

function escHtml(str) {

    .replace(/"/g,'"');
