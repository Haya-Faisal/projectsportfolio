Between Screens

A multi-device, collaborative arcade experience where the game world spans across physical screens.

GitHub Repository Live Demo (Requires 2 Devices)

Impact

Developed a real-time spatial synchronization engine enabling seamless gameplay across multiple mobile browsers with 0% state desync.

Tools

Node.js, Socket.io, p5.js, Express, Device Orientation API

Timeline

March 2026 - March 2026

Core Features

Multi-Screen Synchronization

  • Cross-Device Continuity: Orchestrates snake movement transitions from Screen A to Screen B based on viewport edge collision.
  • Centralized State Authority: Server-side logic for food spawning and score tracking to ensure consistency.
  • Socket-Based Role System: Dynamic assignment of "Screen 1" and "Screen 2" roles upon connection.

Motion-Based Interaction

  • Gyroscope Navigation: Uses real-time accelerometer data to steer the snake, providing a tactile, hardware-integrated feel.
  • Asymmetric Control Mode: Level 2 introduces a mechanic where Device A controls the snake visible on Device B.
  • iOS Permission Handshake: Custom implementation to handle browser restrictions on motion sensor access.

Dynamic Performance Engine

  • Frame-Independent Logic: Moves the snake based on a 320ms interval rather than frame rate for cross-device fairness.
  • Adaptive Difficulty: Real-time modification of movement intervals as scores increase.
  • Low-Latency Communication: Optimized Socket.io payloads for smooth, lag-free steering.

Technical Implementation

Socket.io "Handoff" Logic

// Server-side: Handling the transition between screens
socket.on('snake-exited', ({ side, x, y, snakelenght }) => {
    let otherId = (role === 1) ? screen2 : screen1;
    if (otherId) {
        // Broadcast to the other device that the snake is entering its viewport
        io.to(otherId).emit('snake-entering', { from: side, x, y, snakelenght });
    } else {
        // Safety check: bounce snake back if second screen is missing
        socket.emit('snake-bounce');
    }
});

Device Orientation Integration

// Client-side: Capturing hardware tilt for movement
function handleOrientation(eventData) {
    const movingThreshold = 10;
    let beta = eventData.beta;   // Pitch
    let gamma = eventData.gamma; // Roll

    if (Math.abs(gamma) > movingThreshold) {
        snakedirx = gamma > 0 ? 1 : -1;
        snakediry = 0;
    } else if (Math.abs(beta) > movingThreshold) {
        snakediry = beta > 0 ? 1 : -1;
        snakedirx = 0;
    }
}

Asymmetric Level State Machine

Level 2 Logic: The system swaps the control stream. Screen 1 captures motion data and emits 'tilt' events, which Screen 2 listens for to update its local snake object, creating a "remote-controlled" experience.

Performance & Security

  • HTTPS Implementation: Deployed with SSL certificates to comply with modern browser requirements for the Device Orientation API.
  • Memory Efficiency: Utilizes simple array structures for the snake body to minimize garbage collection overhead during fast-paced movement.
  • Latency Filtering: Implements a 10-degree deadzone threshold on tilt data to prevent "jitter" in movement commands.

Challenges & Solutions

Challenge: State Desynchronization

Solution: Implemented a "Server-as-Source" model for food. Instead of both screens calculating food positions, the server emits 'food-pos' to one screen and 'food-cleared' to the other simultaneously.

Challenge: Viewport Resolution Mismatch

Solution: Standardized the game grid to 20px cells and used relative edge detection (Top/Bottom/Left/Right) rather than absolute pixel coordinates for handoffs.
