Concept

Islamic geometric patterns are built on the Hankin method — a mathematical system of shooting rays from the midpoints of polygon edges and finding their intersections. Every pattern emerges from a single variable: the angle theta. Change the angle, and the entire geometry reorganises.

Naqsh uses this as its core mechanic. Visitors long-press anywhere on the shared canvas to summon the pattern generator, choose their angle by dragging, pick a colour, and place their tile exactly where they pressed. That tile persists on the server — every visitor who opens the page thereafter sees it, layered with all those placed before.

The canvas is a 10,000 × 10,000px world. Visitors navigate it with two fingers. What accumulates over the course of an exhibition is a collective geometric record of every person who touched the screen.

Features

Hankin Geometric Engine

  • Mathematical line generation: Implements the full Hankin method — for each polygon edge, two inward rays are fired at ±theta, intersected using parametric line math, and collected as segment pairs.
  • Three tiling systems: Square-Octagon (4-8-8) and Rhombitrihexagonal (3-4-6-4), each producing a distinct pattern family from the same mathematical process.
  • Bounding-box normalisation: All segment sets are scaled and centred into a fixed tile size regardless of how far the star points extend, so every tile fits its grid cell perfectly.
  • Theta-driven variety: The angle (10°–100°) determines how many star points form, how deep the valleys are, and how complex the crossing lattice becomes. Dragging across the preview canvas changes the geometry live.

Per-Segment Physics

  • Individual line particles: Each of the 20–40 line segments in a tile has its own dx, dy, vx, vy. They are independent physics particles, not a single rigid body.
  • Repulsion: As a finger moves near a tile, each segment's midpoint is tested against the touch position. Segments within the repulsion radius are pushed outward with force proportional to proximity.
  • Ripple propagation: On tap, a ripple wave radiates outward. Each segment receives a Gaussian-weighted push as the wave front passes through its position — a travelling disturbance that physically crosses the pattern.
  • Spring return: All segments spring back to their home positions via a damped spring, so the pattern always reassembles after disturbance.

Collaborative Real-Time Canvas

  • Persistent tile storage: Every placed tile is written to tiles.json server-side. New clients receive all historic tiles on connection and the world rebuilds locally.
  • Live multi-user presence: Touch positions are synced across clients at 50ms throttle. A ✦ symbol marks each connected user's finger — at full opacity for yourself, translucent for others.
  • Shared ripples: Tap-ripples are broadcast to all clients, which spawn the ripple at the same world coordinates and run the physics locally — the wave feels simultaneous without server-side simulation.
  • Grid snapping: The world is divided into 140×140px cells. Each tile snaps to the centre of whichever cell the user pressed, preventing overlap and maintaining the structured grid aesthetic.

Spatial Navigation

  • 10,000 × 10,000px world: The canvas is a fixed viewport into a much larger space. Two-finger drag pans the world with momentum and clamped boundaries.
  • Viewport-only rendering: Grid lines and dots are only computed for cells currently visible, keeping performance smooth across a large world.
  • Tile placement at press position: Long-pressing anywhere opens the generator modal; on confirm, the tile appears in exactly the cell where the press originated.

Sound Design

  • Oud string synthesis: Each interaction triggers a synthesised plucked string — a 40ms filtered noise burst for the attack, followed by a decaying sine fundamental and second harmonic for the resonant body.
  • A minor pentatonic mapping: Segment positions across the world map to notes in the A minor pentatonic scale — central to Arabic and Persian music — so every drag produces harmonically coherent, unplanned melody.
  • Reverb tail: A feedback delay at 180ms adds the resonant quality of a tiled room, connecting the sound to the architectural context of Islamic geometric art.

Hankin Implementation

function hankinLines(verts, theta) {
  const cen = centroid(verts);
  for each edge (a → b):
    mid = midpoint(a, b)
    inwardPerp = perpendicular pointing toward centroid
    rayA = rotate(inwardPerp, +theta)  // from vertex a
    rayB = rotate(inwardPerp, -theta)  // from vertex b
    pt = intersect(rayA, rayB)
    emit segment(a → pt)
    emit segment(b → pt)
}

Per-Segment Physics Loop

for each segment s in tile.segs:
  midpoint = tile.wx + (s.ax + s.bx)/2 * sc + ox

  // Repulsion
  d = distance(midpoint, touchPos)
  if d < RADIUS:
    s.vx += (dx/d) * (1 - d/RADIUS) * FORCE

  // Ripple — Gaussian wave front
  diff = d - (elapsed/1000 * RIPPLE_SPEED)
  if |diff| < RIPPLE_WIDTH:
    s.vx += (dx/d) * gaussian(diff) * FORCE * falloff

  // Spring return
  s.vx += -s.dx * 0.14
  s.vx *= 0.74
  s.dx += s.vx

Challenges & Solutions

Pattern extent vs. tile boundary

Hankin star points extend far beyond the polygon boundary — sometimes 3× the polygon size — so drawing at a fixed scale clips most of the pattern. The solution was to generate all segments at unit scale, compute the true bounding box of all endpoints, then scale and centre that bounding box into the tile. Both preview and main canvas use identical math, so what you see in the modal is exactly what gets placed.

Buffering tiles before world initialisation

The Socket.io historic-tiles event arrives immediately on connection — before the user passes the intro screen and before initWorld() runs. The solution was a pendingTiles buffer: tiles arriving early are queued and flushed inside showMandalaScreen() after the world is ready.

Touch events blocking buttons on mobile

p5.js's touchStarted() returning false calls preventDefault() on all touch events, intercepting button taps. The fix was to check document.elementFromPoint() at the touch coordinates — if the touch landed on a button or modal element, the handler returns early without consuming the event.

Shared ripples without server simulation

Running ripple physics server-side for all clients would require syncing individual segment positions — expensive and complex. Instead, only the ripple origin (x, y) is transmitted. Each client runs the same deterministic physics against that origin, producing the identical wave on every screen without any server simulation.

Exhibition Context

Naqsh was designed for physical exhibition. The recommended setup is a large projection showing the live shared canvas, with mobile devices on a table in front of it. Visitors pick up a phone, long-press anywhere, choose their angle and colour, and watch their tile appear on the wall.

Because every tile persists, the canvas accumulates over time. On the final day of an exhibition, the grid carries the marks of every visitor who came before — a geometric archive of collective presence, built from a mathematical system designed to suggest the infinite.
